# NO2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship NO2 (southern Norway) as its own model with the generic layout plus hydro
features (trailing precipitation and temperature of the catchment points), without `doy`.

**Architecture:**
- **Hydro history:** the six `hyd_*` features need the offset-2 archived forecasts of the
  hydro points for the 90 days up to the end of the anchor day.
  - In training these come from the horizon-1 weather that is already loaded.
  - At runtime one extra previous-runs request with `past_days` fetches them.
  - The backfill fetches 90 more days of them before its first anchor.
- **Core interface:** the history goes into core as a separate mapping of offset-2 series, so
  training and runtime build the features with the same code.

**Tech Stack:** numpy (core), scikit-learn 1.9.1 (training), Home Assistant tests.

**Spec:**
- Research: `research/zones/README.md`, variant `hydrel` = `hydnd` (hydro features, no `doy`) +
  `rel`. Code: `research/zones/bt.py` (`dataset`, `relative`), `research/zones/genfeat.py`
  (`feature_names(cfg, hydro_extra=True)`, `_weather_features`, `_hydro_extra`, the `fc_sum`
  loop in `build_features`), `research/zones/zonecfg.py` `ZONES["NO2"]`.
- Research run `research/data/zones/out/pred_NO2_hydrel_600.pkl` has 51 features (`meta["names"]`
  is the target list) and the following results.
  - Production setting: monthly refit, 600 iterations.
  - Window: issue days 2025-10-01 … 2026-10-20, 55,080 rows.
  - MAE in ct/kWh per horizon D+1…D+6: 1.55 1.64 1.77 1.82 1.89 1.94.
  - All horizons: 1.77, bias −0.47, skill 0.293.
  - For comparison: `hydro` (with `doy`, absolute) 2.11; `base` 2.53.
- Base branch: `zones-dk` (DK1/DK2), which stacks on `zones-nl` → `schema-2`.

## Decisions

### Zone (`core/zones.py`)

- **Points:**
  - Catalogue additions with `N_VARS` and the research coordinates:
    `no2_kristiansand, no2_stavanger, no5_sogn, no1_hallingdal, no5_bergen, no1_oslo`.
  - `no2_sirdal` already exists.
- **`NO2 = Zone(...)`, roles verbatim from research:**
  - `code="NO2"`, `name="Southern Norway"`, `tz="Europe/Oslo"`, `country="NO"`,
    `layout="generic"`, `default_vat=25.0`.
  - `own=("nb_no_south", "no2_kristiansand", "no2_stavanger", "no2_sirdal")`.
  - `wind=("no2_kristiansand", "no2_stavanger")`, `solar=()`.
  - `hydro=("nb_no_south", "no2_sirdal", "no2_stavanger")`.
  - `nb=("nb_dk_west", "north_sea", "schleswig", "nb_nl", "no5_bergen", "no5_sogn", "no1_oslo",
    "no1_hallingdal")`.
  - `nb_wind=("nb_dk_west", "north_sea", "schleswig", "nb_nl")`.
  - `nb_hydro=("no5_sogn", "no1_hallingdal", "no5_bergen")`.
- **New zone fields:**
  - `hydro_extra: bool = False`; NO2 sets True.
  - `doy: bool = True`; NO2 sets False, which drops the `doy` column.
- **`Zone.hydro_points`:** property, `tuple(dict.fromkeys(self.hydro + self.nb_hydro))`. It is
  the six points `_hydro_extra` sums over, in that order.
- **`ZONES` order:** DE-LU, NL, DK1, DK2, NO2.

### NO holidays (`core/calendar.py`)

- Same days as research `offdays("NO", y)`: `holidays.country_holidays("NO")` plus 24 and 31 Dec.
  Check genfeat line 59 for the exact rule.
- Hand-code `no_holidays(year)` for 2020–2040.
  - The package includes every Sunday for NO in some versions. Look at what 0.107 returns, and
    mirror exactly what the research `offdays` used.
- Test against the package plus the eves, as for DK.

### Features (`core/features.py`)

- **Names:**
  - `feature_names(NO2)` must equal research `meta["names"]` of `pred_NO2_hydrel_600.pkl`:
    51 names, no `doy`, the six `hyd_*` last.
  - Pin the list in a test, hard-coded and not read from the pickle.
- **Hydro features, ported byte-for-byte from `_hydro_extra` and the `fc_sum` loop:**
  - `hyd_precip_past{14,30,90}`: the `nansum` over the hydro points of the offset-2 precipitation
    in the `days × 24` hours before `known_until`.
  - `hyd_temp_past{14,30}`: the mean over the points of the `nanmean` of the offset-2 temperature
    over the same windows.
  - `hyd_precip_fc6`: the `nansum` of the hydro points' precipitation in the forecast weather over
    all six target days (the final `fc_sum`). It is the same value on every row of the anchor.
- **Interface:** the feature builder gets `hydro_history: Mapping[str, Hourly] | None`, keyed
  `"{point}__{var}"` and holding offset-2 series.
  - Training passes `weather[1]`, the horizon-1 series, which is exactly research's `s1`.
  - Runtime passes the history fetch.
  - It is required when `zone.hydro_extra` and ignored otherwise.
- **`rel`:** unchanged. The `hyd_*` columns stay absolute, as in research `relative()`.
- **Parity test:**
  - `build_features` for NO2 must equal research genfeat with `hydro_extra=True` and without
    `doy`, on a slice of the real dataset. Skip without `research/data`.
  - Exception: the documented DST wall-clock lag columns, as in the NL/DK parity tests.

### Runtime history fetch (`sources/open_meteo.py`)

- **`fetch_hydro_history(session, zone, *, run_blocking) -> dict[str, Hourly]`:**
  - One request to `PREVIOUS_RUNS_URL` for `zone.hydro_points`.
  - Parameters:
    - `hourly=precipitation_previous_day2,temperature_2m_previous_day2`
    - `models=ecmwf_ifs025`, `past_days=92`, `forecast_days=2`, `timezone=GMT`
  - Parsed with suffix `_previous_day2`.
  - Size cap `MAX_WEATHER_BYTES` (check the body fits; raise the cap only if needed).
- **Completeness:**
  - Before forecasting, check that every hydro point has no missing hour in the 90 days before
    `known_until`.
  - A gap raises `SourceError` naming the zone, so the run fails into the existing
    retry/backoff.
  - Never forecast with `nansum` over holes at runtime: a hole silently lowers the precipitation
    sums.
- **Coordinator:** calls `fetch_hydro_history` only for zones with `hydro_extra`. For NO2 that
  is one more Open-Meteo request per run; the other zones' runs are unchanged.

### Backfill (`backfill.py`)

- **Ranges:** the normal previous-runs fetch stays as it is (all point sets, all offsets, from
  the first anchor).
- **Hydro history:** for a `hydro_extra` zone, add a separate fetch of only the hydro points for
  the range (first anchor − 91 days) … (last anchor + 1).
  - Columns `precipitation_previous_day2,temperature_2m_previous_day2`, month chunks,
    `REQUEST_PAUSE` apart.
  - For one year of backfill that is about 15 extra small requests. Do not widen the full point
    sets by three months.
  - Implement it as `fetch_hydro_history` with optional `start`/`end` (instead of
    `past_days`), so runtime and backfill share the parser.
- **History use:** pass that history as `hydro_history` for every backfilled anchor.
- **Meaning:** the backfill-days option keeps its meaning (days of forecasts), not days fetched.
- **Tests:**
  - The hydro request range for NO2.
  - The DE-LU backfill makes exactly the requests it made before.

### Training (`training/`)

- **Fetch:** `fetch.py --zones NO2` gets the new points.
  - Raw files may be seeded from `research/data/zones/weather` when the format matches, as the DK
    phase did. Document what was copied in `tests_ha/fixtures/README.md` / commit message.
- **Run:**
  - `train.py --zone NO2`: own model only, with no parent and no price inputs.
  - The earliest anchors have partial 90-day windows (the data starts 2024-03). Keep research's
    behaviour (`nansum`) in training for parity, and say so in a comment.
- **CI:**
  - Add NO2 to `training/ci_zones.py` after DK2. It is independent of DE-LU, so a DE-LU error
    does not skip NO2.
  - Measure the local NO2 training time and estimate the five-zone CI run.
  - If it is over ~300 minutes, report rather than change the job layout.
- **Bundled model:** `no2-2026-10` (cutoff 2026-10-01) with its backfill file, in
  `custom_components/spot_forecast/models/` and `tests_ha/fixtures/model/`, in its own commit.

## Acceptance

- **Gate:** walk-forward on the gate window (issue days from 2025-10-01) gives MAE ≤ 1.85 ct/kWh
  over all horizons and skill ≥ 0.25.
  - Report per horizon, bias and P90 exceedance (target 9–15 %).
  - Also report the research numbers restricted to the same rows (targets before 2026-10-01),
    as the DK phase did.
- **Below the limits: STOP and report.** Do not tune features to pass.

## Review Focus

- **Hydro history with one missing hour** (Open-Meteo gap) → the run fails with a `SourceError`
  naming NO2, there is no forecast with deflated sums, and a retry follows (HA test with a
  fixture that has a hole).
- **Fall-back day 2026-10-25 in Europe/Oslo** → the 90-day windows count real hours (2160 back
  from `known_until`), not wall-clock days (pure test, equal to research).
- **Backfill start for NO2** → 91 days before the first anchor. A DE-LU backfill makes exactly
  the requests it made before (test on request URLs).
- **Runtime hydro history equals training's `weather[1]`** on overlapping hours: a pure test
  with a recorded `past_days` body against the previous-runs `_previous_day2` columns of the
  same points and hours.
- **NO2 next to DE-LU in one HA instance** → two entries, independent runs, and only NO2 makes
  the history request (HA test on the request log).
