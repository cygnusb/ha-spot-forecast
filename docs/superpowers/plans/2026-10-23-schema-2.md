# Feature Schema 2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `FEATURE_SCHEMA = 2` for DE-LU: price-level features relative to the 7-day mean
(`rel`) and price lags at the same local wall-clock hour across DST, with a retrained bundled
model, regenerated fixtures and updated figures.

**Architecture:** Both changes live in `core/features.py` (shared by training and the
integration, so there is no train/serve skew). The bundled model is retrained locally with
the existing pipeline and cutoff 2026-10-01, so every date the HA tests depend on stays valid.

**Tech Stack:** numpy (core), scikit-learn 1.9.1 (training), Home Assistant tests.

**Spec:** research results of 2026-10-23: `research/zones/` (rel, `bt.py: relative()`),
`research/holidays_dst/` (`build.py: dst_lags()`), summary in `research/README.md` and the
session report (DE-LU production setting: MAE 2.35 → 2.20 ct, bias −0.63 → −0.28).

## Global Constraints

- `core/` stays numpy-only; the Pi does inference only.
- Minimum Home Assistant 2024.11.
- Definitions are ported byte-for-byte from the research code; the backtest numbers only
  transfer if they are identical.
- Commit messages in the repo style with the session attribution lines; no push.

## Decisions

- **rel:** after the features are built, for the columns `p_lastday, p_lastweek, D_mean, D_min,
  D_max, D_mean30, D_min7, D_max7, D_gq_evening14, D_gq_q90_14`: `(x − D_mean7) / scale`; for
  `D_std, D_std7`: `x / scale`. `D_mean7` and everything else stay absolute. `scale` is the
  existing per-anchor target scale. Feature names stay the same (the schema number marks the
  meaning change).
- **DST lags:** `p_lastday`/`p_lastweek` take the price at the same local wall-clock hour on
  day (target − h) / (target − 7); ambiguous times take fold=0, nonexistent ones the hour
  before; hours at or after `known_until` read NaN (as today). Vectorised implementation in
  core (no per-row Python loop over 137k rows in training is required for correctness, but
  keep training time reasonable); must equal `research/holidays_dst/build.py: dst_lags` on the
  full dataset (test).
- **Bundled model:** retrained with cutoff 2026-10-01 → version `de_lu-2026-10`, the same string
  as the published schema-1 asset. Harmless (manifest entry has schema 1 and equal cutoff →
  clients don't download). The first schema-2 *publish* must have a later cutoff (the 3.11 run
  → `de_lu-2026-11`) and needs the manual `accept_incomparable` dispatch (the gate cannot load
  the schema-1 model).
- **Old clients (v0.1.2):** `wants_download` skips an entry with another schema. Verify on
  `git show v0.1.2:custom_components/spot_forecast/core/manifest.py` (+ model_update) that a
  schema-2 entry is skipped without an error or a repair issue.
- **Release path:** `tools/fetch_published_model.py` must keep the committed model (exit 0) when
  the published entry's `feature_schema` differs from the code. Verify and test.

## Review Focus

- A schema-1 model downloaded earlier and lying in `.storage` → rejected, deleted, bundled
  schema-2 model used, no repair issue (test in `tests_ha/test_model_update.py`).
- Fall-back day 2026-10-25 and spring-forward 2027-03-28: lags at the right wall-clock hour,
  no NaN for the last hour of the fall-back day (pure test).
- rel on an anchor whose `scale` sits at the floor (`scale_floor`) → finite features.
